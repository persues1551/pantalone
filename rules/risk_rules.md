# risk_rules.md — 风险控制

## 投资风险

| 规则 | 说明 |
|------|------|
| 单票仓位 | 不超总仓位25% |
| 股票止损 | 唯一采用 `rules/pool_rules.md` 的 A+/A/B/C 权威池规则；价格、风格或“价值-技术共振”不得另设统一百分比 |
| 独立风险评估 | 有证据时可提出比池规则更严格的动态条件，但必须说明依据和失效条件 |
| 连续两天下跌 | 形成减仓风险建议，不自动执行 |
| 情绪高潮 | 不追涨 |
| 恐慌中 | 不割肉 |
| 模拟盘纪律 | = 实盘纪律 |

默认只生成待执行建议。任何生产减仓、清仓、卖出、观察池或模拟盘状态写入，必须获得用户明确授权。

## 建仓候选证据与资格门槛

**核心原则**：评分、技术、量价、消息、资金和大盘状态只提供研究证据，不能直接生成建仓动作、仓位或分批计划。只有全部资格门槛同时通过，才能形成待授权建仓候选；生产买入必须获得用户对该动作的逐次明确授权。

### 一、研究证据评分（满分100分）

| 维度 | 权重 | 评分标准 |
|------|------|----------|
| 板块强度 | 25分 | 当日板块涨幅>1%=20分，>2%=25分，<0%=0分 |
| 技术位置 | 25分 | RSI 40-60=25分，60-70=20分，>75=5分（超买扣分） |
| 量价配合 | 20分 | 放量突破=20分，缩量上涨=10分，放量下跌=0分 |
| 消息催化 | 15分 | 重大利好(+4以上)=15分，一般利好=10分，无消息=5分 |
| 资金流向 | 15分 | 主力净流入>5000万=15分，>0=10分，净流出=0分 |

评分结果仅记录证据强弱和缺口。任何总分或单项分都不得直接映射为建仓建议、买入动作、固定仓位或分批比例。

### 二、完整建仓资格门槛

以下条件必须全部通过，缺一项即不形成建仓候选：

1. 数据时点、来源和关键字段完整，核心数字完成交叉核验；
2. OCIFQ逻辑、催化、成功标准、失败标准和验证时间明确；
3. 风险排雷与合规审查完成，Critical或Major风险未关闭时阻断；
4. 技术、模型、情绪、资金和版本信号只作证据，不独立决定动作；
5. 风险收益比、失效条件和权威A+/A/B/C池止损可以计算；
6. 当前同一股票暴露、组合暴露、流动性和可交易数量已核对；
7. 候选总暴露不超过25%，且最小一手不会突破上限；
8. 授权状态明确为“待用户逐次授权”，不得假定已有权限。

### 三、风险预算计算

候选仓位由当前同票暴露、组合剩余风险预算、流动性、失效条件和最大可承受损失共同计算。输出必须展示计算依据；不得按评分档位套用10%/15%/20%/25%的固定仓位。

**绝对上限**：同一股票的底仓、波段仓、机动仓和其他名义仓位合计不得超过25%。

**高价股处理**：如果1手（100股）金额超过25%单票上限，则不生成建仓建议，不以“最小交易单位”为由突破风险上限。

### 四、待授权分批方案

只有完整资格门槛全部通过后，才可以根据流动性、价格区间和风险预算提出分批候选方案。方案必须满足：

- 所有批次合计不超过已计算的候选风险预算和25%单票上限；
- 不使用固定50/50或其他脱离当次数据的批次比例；
- 每批明确价格依据、数量、失效条件和授权状态；
- 未获得用户对该批次的明确授权时，不写模拟盘、不下单、不改变任何持仓或观察池状态。

### 五、市场与技术证据

大盘状态、RSI、量价、消息和资金流用于解释证据强弱或阻断高风险候选，不得直接生成积极/常规建仓建议、固定组合暴露或减仓动作。ST/退市、停牌、数据严重缺失等硬风险可以阻断候选，但不能反向推导出交易动作。

### 六、候选研究排序

同一天有多个候选时，可以按证据完整度、风险关闭状态、流动性和OCIFQ逻辑质量排序。排序只决定研究优先级，不决定买入顺序、仓位或授权状态。

## 股票退出合同

**核心原则**：股票止损唯一采用 `rules/pool_rules.md` 的 A+/A/B/C 权威池规则；止盈唯一采用本节的 +12%/+20%/+30% 阶梯。均线、持仓天数、板块资金和其他技术条件只能作为复核证据，不得单独生成减仓、清仓或卖出建议。

### 分批止盈

| 浮盈 | 建议动作 | 理由 |
|------|------|------|
| +12% | 建议卖出1/3 | 避免过早止盈，给趋势空间 |
| +20% | 建议再卖出1/3 | 大部分利润已锁定 |
| +30% | 建议剩余1/3跟踪止盈 | 让利润奔跑 |

**注意**：分批止盈按股数取整至100股。若持仓仅100股，+12%时卖出全部（无法分1/3）。

### 风险复核证据

| 证据 | 用途 | 禁止事项 |
|------|------|----------|
| MA5/MA10位置 | 判断趋势强弱，解释风险变化 | 不得单独触发减仓、清仓或卖出 |
| 持仓天数 | 提醒复核原始逻辑和催化剂 | 不得按固定天数强制退出 |
| 板块资金流 | 判断行业环境是否恶化 | 不得绕过权威池止损与止盈阶梯 |

### 每日检查流程

```
1. 是否触及 A+/A/B/C 权威池止损？→ 生成对应止损建议
2. 浮盈是否达到 +12%/+20%/+30%？→ 生成对应分批止盈建议
3. 均线、持仓天数和板块资金是否提示风险变化？→ 仅补充证据和复核说明
4. 所有生产动作均等待用户对该动作逐次明确授权
```

## 研究风险

- 不把相关性当因果性
- 不把个案当规律
- 不把假设当结论
- 不把单一来源当事实

## 写作风险

- 不编造引用
- 不伪造数据
- 不把推测写成事实

## 通用风险

- 不承诺收益
- 不保证结果
- 不鼓励违法违规
- 不在高风险领域装作权威

## 技术风险（v2.5 新增）

核心禁止项：
- 假装已执行用户环境中的操作
- 编造不存在的配置
- 在状态不明时继续修改系统
- 无回滚方案地修改关键文件

## Token 优化（v1.14）

> **教训（2026-05-12 审计）**：实测全天消耗 1,162 万 token（常规输入），加上推理 token 后平台账单约 **5,000 万/天**。输出仅占 <1%——输出压缩是伪需求。真正的大头：①上下文累积（85%）②推理 token（reasoning_effort: medium 产生 3-8x 隐性消耗）③工具定义重发（10%）。

> **主人决策（2026-05-12）**：**质量优先于成本。** 投资分析质量不得为省 token 而妥协。优化方向仅限于**不影响分析质量的基础设施层**：工具裁剪、会话管理、缓存利用。

### Cron Job 工具集限制（必须）

**所有 Amadeus cron job 必须设置 `enabled_toolsets`**，只保留实际用到的工具：

```yaml
enabled_toolsets: ["terminal", "web", "file"]
```

效果：工具定义从 29 个（~11,400 tok/轮）→ 4-6 个（~1,500 tok/轮），每 session 省 ~10,000 token。

## 会话管理纪律

- **任何会话超过 15 轮（user turns）→ 主动 `/new` 重置上下文**
- 44 轮长会话实测消耗 308 万 token，拆成 3 个 15 轮仅需 ~150 万 token
- 完成一个独立任务后（如修复脚本、调试 cron），立即 `/new` 开始下一个任务
- cron 推送会话天然只有 1 轮，无需处理

## 输出不优化原则

- 输出 token 占比 <1%，压缩输出是 ROI 最低的优化方向
- 不要为了省 token 而降低分析质量、删除风险声明、压缩数据核验
- 如果未来输出显著增长（如 deep research 模式），再评估

## DeepSeek Context Caching（已自动启用）

DeepSeek KV Cache **默认开启**，无代码修改：缓存命中仅收原价 1/10。但要求**精确前缀匹配**——长会话中前缀不断膨胀，缓存命中率骤降。

## 推理 Token（沉默杀手）

`reasoning_effort: medium` 使模型每输出 1 token 前做 3-8x 内部推理。推理 token 不在 session JSON 中，只出现在平台账单。

支持 effort 值：`none`/`minimal`/`low`/`medium`/`high`/`xhigh`。

简易任务（盘前早报、系统检查）可用 `low` 省 40%，但目前不支持 per-job 设置。
